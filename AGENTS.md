# Agent guidance — php-io-extensions/raven

1. **Read [`.okf/index.md`](.okf/index.md) first** before changing the API, the C, the generator or packaging. Open only the concepts the change touches. The design spec is [`docs/superpowers/specs/2026-11-12-raven-design.md`](docs/superpowers/specs/2026-11-12-raven-design.md).
2. **Bindings are 1:1 at Raven main `4eaba42`** (library still reports 0.2.3): every function `Raven.h` declares but `Rmemory_alloc`, `Rmemory_realloc`, `Rmemory_free`, `Rpixels_alloc`, `Rpixels_free` (1,278 functions). Function, struct, enum and constant names are the C names. No defaults, no composites. The spec's "Names and translations" lists every translation; there are no others.
3. **Upstream is copied unchanged** into `lib/raven/` (`include/`, `src/`, `third_party/`, `LICENSE`, `NOTICE`, `THIRD_PARTY.md`) and Khronos Vulkan-Headers v1.3.290 into `lib/vulkan-headers/`. Never edit either. `config.m4` compiles exactly the sources upstream's CMake does with `RAVEN_BUILD_WEB=OFF`, with its flags. On `0.11.x-nightly`, a new Raven is a new upstream main commit: replace `lib/raven/`, re-extract, diff `tools/api.json`, regenerate, update tests, bump `PHP_RAVEN_UPSTREAM_COMMIT`.
4. **Vulkan is Raven's own.** Raven opens the Vulkan loader at run time; nothing links Vulkan and ext-vulkan is not involved. Vulkan handles cross as `int` addresses.
5. **The binding is generated.** `clang -Ilib/raven/include -Xclang -ast-dump=json -fsyntax-only tools/ast.c | php84 -d memory_limit=-1 tools/extract.php > tools/api.json`, then `php84 tools/generate.php` (prints `bound N, manual M, not bound K, pending P`; P must be 0), then `php84 /opt/homebrew/opt/php@8.4/lib/php/build/gen_stub.php -f stubs`. Commit `tools/api.json`, stubs, arginfo and `src/gen/` together. Never hand-edit `src/gen/`, `stubs/raven_*.stub.php` or `*_arginfo.h`. A shape the generator does not know goes into the generator, or into `tools/bindings.php` `manual` with its function in `src/manual.c` and its stub in `stubs/manual.stub.php`.
6. **The stub is the declaration.** A `ZEND_FUNCTION` is written out, never made by a macro.
7. **Callables run on the PHP thread that owns Raven, nowhere else.** Raven's workers and render thread hand calls to it (`src/threads.c`) and take the no-op result past a deadline. Read [`.okf/architecture/callbacks.md`](.okf/architecture/callbacks.md) before touching slots, trampolines or the queue.
8. **Build.** `./install-macos.sh` into Homebrew `php@8.4` (`php84`) and `php@8.4-zts` (`zhp`). Debian: `./install-debian-trixie.sh` (needs `libx11-dev`, `pkg-config`); copy the tree to the Pi with `COPYFILE_DISABLE=1 tar --no-xattrs` so no `._*` files reach gen_stub. Pest at `XDEBUG_MODE=off php -d memory_limit=128M vendor/bin/pest` on both builds. Gate a commit on the suite's exit code. After a generator change, `php84 tools/sweep.php` (crash sweep, ~10 min).
9. **No windows on the maintainer's screen.** Tests run Raven headless on `R_BACKEND_NULL`. Never open a real window, play with the clipboard or open a URL without asking first.
10. **Durable facts go in `.okf`.** Update the matching concept, bump its `generated.at`, append `.okf/log.md`.
11. **Version** is `PHP_RAVEN_VERSION` in `php_raven.h`: 0.11.0, venusian/framework's 0.x line. `os-families`: linux, darwin.
